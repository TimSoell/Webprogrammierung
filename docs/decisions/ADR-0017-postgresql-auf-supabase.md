# ADR-0017 — PostgreSQL bei Supabase, Sitzungen in der Datenbank

**Status:** angenommen
**Datum:** 2026-09-30

## Kontext

Mit dem Umzug auf Vercel ([ADR-0016](ADR-0016-hosting-auf-vercel.md)) gibt
es keine MySQL-Datenbank aus XAMPP mehr, auf die die Seite zugreifen könnte.
Gebraucht wird eine Datenbank, die aus dem Internet erreichbar ist und
nichts kostet.

Dazu kommt ein zweites Problem: PHP legt Sitzungen als Datei ab. Auf Vercel
läuft jeder Aufruf in einer Funktion ohne gemeinsame Festplatte – eine
Sitzungsdatei aus dem Login-Aufruf sieht der nächste Aufruf nicht. Der Login
ginge zufällig verloren.

Der Dozent hat zugestimmt, dass PostgreSQL statt MySQL verwendet wird.

## Entscheidung

Die Daten liegen in **PostgreSQL bei Supabase**, Region Frankfurt
(`eu-central-1`). Supabase wird **nur als Datenbank** benutzt – nicht Supabase
Auth, nicht die JavaScript-Bibliothek, nicht die REST-Schnittstelle. Der Weg
bleibt: Service → Endpunkt → Repository → PDO.

- **Zwei Projekte:** `schwitzkasten-dev` für lokal und Preview, ein eigenes
  für Produktion. `seed.sql` läuft nie gegen Produktion, außer einmal beim
  Einrichten.
- **Verbindung über den Pooler im Session-Modus** (Port 5432). Die direkte
  Adresse ist im kostenlosen Plan nur per IPv6 erreichbar, und der
  Transaktions-Modus (Port 6543) kann keine Prepared Statements – die
  Login-Bibliothek erzwingt aber welche.
- **Eine Verbindung pro Aufruf.** Die Login-Bibliothek bekommt dieselbe
  PDO-Verbindung wie die Repositories (`src/Auth.php`).
- **Sitzungen in der Tabelle `sitzungen`** über `src/SitzungsSpeicher.php`
  (von PHP aufgerufen) und `src/Repositories/SitzungRepository.php` (das SQL).
  Lokal genauso, damit sich beide Umgebungen gleich verhalten.
- **Zeitzone Europe/Berlin** in der Datenbank (`ALTER ROLE` in `schema.sql`)
  und in PHP (`src/bootstrap.php`).
- **Row Level Security auf jeder Tabelle, ohne Policies.** Damit liefert
  Supabases öffentliche REST-Schnittstelle keine einzige Zeile. Die App ist
  Eigentümerin der Tabellen und davon nicht betroffen.
- **Die Login-Bibliothek bleibt** ([ADR-0005](ADR-0005-login-bibliothek.md)).
  Sie bringt ein offizielles PostgreSQL-Schema mit, das `schema.sql` wörtlich
  übernimmt.

Übersetzungsregeln für neue Tabellen:

- `integer GENERATED BY DEFAULT AS IDENTITY` statt `AUTO_INCREMENT`
- `text` mit `CHECK (spalte IN (...))` statt `ENUM`
- `smallint` mit `CHECK (spalte IN (0, 1))` statt `TINYINT(1)` – damit
  `WHERE aktiv = 1` gültig bleibt
- `timestamp(0) DEFAULT LOCALTIMESTAMP(0)` statt `TIMESTAMP DEFAULT
  CURRENT_TIMESTAMP` – PHP bekommt dann wie bisher `2026-09-30 18:00:00`
- Indizes als eigene `CREATE INDEX` mit Tabellennamen im Indexnamen;
  **Fremdschlüssel brauchen einen eigenen Index**
- `INSERT … ON CONFLICT … DO UPDATE` statt `ON DUPLICATE KEY UPDATE`;
  doppelter Schlüssel meldet SQLSTATE `23505` statt `23000`
- `CURRENT_DATE` statt `CURDATE()`, `LOCALTIMESTAMP` statt `NOW()`
- Jede neue Tabelle bekommt `ENABLE ROW LEVEL SECURITY`

## Konsequenzen

**Positiv**

- Eine Datenbank für das ganze Team statt fünf lokaler, die auseinanderlaufen.
- Kostenlos, in Frankfurt, mit Table Editor im Browser statt phpMyAdmin.
- Der Login hält auf Vercel, egal welche Instanz antwortet.

**Negativ**

- **Ohne Internet läuft lokal nichts mehr**, auch nicht die Startseite –
  jede Seite liest ihre Sitzung aus der Datenbank.
- Jeder Aufruf baut eine Verbindung nach Frankfurt auf; spürbar langsamer
  als MySQL auf `localhost`.
- **Supabase pausiert kostenlose Projekte nach sieben Tagen ohne Zugriff.**
  Vor Vorführungen prüfen.
- Im kostenlosen Plan darf jede Person, die Admin der Organisation ist,
  insgesamt nur zwei aktive Projekte haben – über alle ihre Organisationen.
- Das Team teilt sich die Entwicklungsdatenbank. Wer `seed.sql` einspielt,
  löscht die Buchungen aller anderen.
- Sitzungen ohne Sperre: Zwei gleichzeitige Aufrufe derselben Person können
  sich beim Speichern überschreiben. Da sich der Inhalt nur beim An- und
  Abmelden ändert, ist das hinnehmbar.
- `schema.sql` und `seed.sql` mussten einmal komplett übersetzt werden, sechs
  Repositories an einzelnen Stellen.

## Verworfene Alternativen

**Weiter MySQL, bei einem Anbieter im Netz.**
Kein Übersetzen nötig, aber die kostenlosen Angebote sind knapp oder
befristet, und im Team war Supabase bereits eingerichtet.

**Supabase Auth statt delight-im/auth.**
Hätte den kompletten Login neu gebaut und JavaScript direkt mit der Datenbank
sprechen lassen – an den Schichten vorbei.

**Sitzungen nur über „Angemeldet bleiben"-Cookies der Bibliothek.**
Hätte ohne neue Tabelle funktioniert, wäre aber ein Umweg: jeder Aufruf ohne
Sitzung hätte sich über das Cookie neu angemeldet.

**Transaktions-Modus des Poolers (Port 6543).**
Für Serverless eigentlich empfohlen, aber ohne Prepared Statements – die
Login-Bibliothek schaltet sie fest ein.
